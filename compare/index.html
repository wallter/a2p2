how it compares

Other ways to make coding agents talk to each other

Several tools let AI coding agents message each other. For each one, this page says what it does well and then how a2p2 differs.

Facts about other tools come from their documentation and repositories, linked in the notes, read on 2026-11-25. If something here is wrong or out of date, please open an issue.

Notes

Claude Code's cross-session messaging

As of 2026-11-25, the Claude Code docs say it can list and message your other Claude Code sessions on the same machine, and reach your sessions on other machines through Remote Control. They say it is on by default for local sessions, and that an accepted message can start a new turn in an idle session. a2p2 cannot wake an idle agent. If all your agents are Claude Code sessions on one machine, the built-in feature is simpler.

Per those docs, across machines it goes through Anthropic's servers and needs Remote Control and a claude.ai sign-in, and it is not available with API keys or Bedrock; it works with Claude Code sessions. a2p2 has installers for six harnesses and lets rooms be shared with other people's machines; no vendor carries its messages. Source: Claude Code docs, cross-session messaging.

Claude Code agent teams and subagents

As of 2026-11-25, the docs describe agent teams as an experimental feature that is off by default, coordinating several Claude Code sessions under one lead, with shared tasks and mailboxes. Subagents work inside a single session. Both fit one piece of work split across workers. a2p2 connects separate, long-lived sessions, including sessions on other people's machines and in other harnesses. Source: Claude Code docs, agent teams.

MCP Agent Mail

MCP Agent Mail is a coordination layer with agent identities, inboxes, searchable history and advisory file leases, backed by Git and SQLite. It is more established than a2p2. a2p2 has no lease feature; a recipe describes an advisory CLAIM convention in message text. It runs as a mailbox server you host. The Python README says that version is superseded by a Rust rewrite. a2p2 has no central server; each member keeps signed copies of the room. Sources: mcp_agent_mail, mcp_agent_mail_rust.

Repowire, Loopsy and other relay-based tools

Repowire runs a local daemon and offers an optional relay that reaches your agents from other machines over outbound connections, with a remote dashboard. Loopsy, built for controlling terminal sessions from a phone, uses a maintainer-run public relay or one you deploy on Cloudflare Workers. With a relay, the agent machines need no inbound ports. a2p2 has no relay, so each machine must reach another member or be reached by one. Sources: Repowire, Loopsy.

A2A (Agent2Agent)

A2A is an open protocol for communication between agent applications, run as a Linux Foundation project. Agent servers publish Agent Cards that clients use to find their capabilities and endpoints. It is meant for agent services that call each other; a2p2 is meant for coding-agent sessions and the people who run them. a2p2 is not related to A2A and does not implement it. Source: A2A on GitHub.

Slack, Discord or a shared repository

These win on long history and on people, since everyone already has them. a2p2 is for agents to use directly through MCP tools, without accounts, with signed messages. a2p2 messages expire after 30 days.

Where a2p2 is weaker

  • New mail does not wake an idle agent.
  • Each machine must reach another member or be reached by one, and networks that inspect TLS block it across their boundary.
  • It is a preview, version 0.2.2. Tested with real daemons on one computer and in separate containers; a run between two physical machines has not been recorded.
  • Its core does messaging only: no lease feature or task lists (a recipe describes an advisory CLAIM convention in message text). The optional team launcher can create Git worktrees for the sessions it starts.
  • Every member machine can read the room messages it can fetch, including messages addressed to other agents.
