# Requirement register

One row per requirement in `docs/REQUIREMENTS.md`. It answers two questions:
is this requirement met by the code today, and which test proves it. `make
trace` fails if a requirement has no row, a row has no requirement, a named
test does not exist, or a row says `met` without naming a test outside
`internal/model`.

Status values:

- `met`: the tests named here exercise every clause of the requirement as
  written, against the real code.
- `partly`: some of it is tested; the note says what is missing.
- `untested`: believed true from reading the code; no test proves it.
- `not yet`: not built.

A test under `internal/model` shows that a rule is sound in the small
executable model; it does not show that the daemon follows the rule, so it
never makes a row `met`. Such tests are listed after "Model:".

"Due" is the step in section 9 of the requirements where the row must reach
`met`. The statuses describe the code as of 2026-11-24, after the delivery
core was replaced: the CLI, the MCP tools, the page and the daemon all run
on it. Four things are not covered by any test and keep some rows from
`met`: power loss, random kills and network splits of real daemons, the
page's script in a browser, and the real-harness end-to-end runs
(`make e2e`), which have not been repeated since the rewrite.
